# كاشير المقهى + الولاء — منطق العمل (مواصفات البناء)

> مرجع البناء التفصيلي. يُقرأ مع `CAFE-POS-PLAN.md` (الخلفية والقرارات).
> **مشروع منفصل** — يُنقل لمستودعه عند الإنشاء. الحالة: مواصفات، لم يبدأ الكود.
> الأرقام المعلّمة **(تأكيد)** تحتاج حسم المالك قبل البناء.

---

## ٠) نطاق النسخة الأولى (MVP)
بيع سريع · دفع كاش/بطاقة · طباعة فاتورة · خصم مخزون بالوصفات · جرد وفرق · ورديات ودرج · صلاحيات · تقرير استثنائي · ولاء ختم · لوحة مالك بتنبيهات.
**مؤجّل:** offline كامل · موافقة إلغاء عن بُعد · ربط كاميرا تلقائي · تعدّد فروع.

---

## ١) نموذج البيانات (كيانات)

**المواد الخام `materials`:** id · الاسم · وحدة الحساب (`gram`|`ml`|`piece`) · المخزون الحالي (بوحدة الحساب) · تنبيه انخفاض.
- أمثلة: حبوب (gram) · حليب (ml) · كوب سفري (piece) · غطاء (piece).

**المشروبات `drinks`:** id · الاسم · الفئة (ساخن/بارد/إسبريسو) · السعر · مؤهّل للولاء (bool) · **المحصول** (ربط بحبوب معيّنة) · نشط.

**الوصفة `drink_materials`:** drink_id · material_id · الكمية.
- مثال «لاتيه»: حبوب ١٨g · حليب ١٨٠ml **(تأكيد)** · كوب ١ (للسفري) · غطاء ١ (للسفري).
- «إسبريسو سنكل»: حبوب ٩g. «تقطير»: حبوب ٢٠g.

**الموظفون `employees`:** id · الاسم · رمز دخول (PIN) · الدور (`owner`|`barista`).

**الورديات `shifts`:** id · employee_id · بداية · نهاية · فكّة افتتاحية · كاش معدود ختامي (أعمى) · الفرق (يُحسب).

**الطلبات `orders`:** id · رقم · shift_id · employee_id · customer_id (اختياري) · الحالة (`open`|`paid`|`voided`) · طريقة الدفع (`cash`|`card`) · الإجمالي · الوقت.
**بنود `order_items`:** order_id · drink_id · الكمية · سعر الوحدة · هل مجاني (bool) · سبب المجاني (ولاء/…).

**سجلّ الهدر `waste_log`:** material_id · الكمية · السبب (`dial_in`|`spill`|`expired`|`remake`) · employee_id · الوقت.

**سجلّ التدقيق `audit_log`** (لا يُمحى): النوع (`void`|`refund`|`discount`|`free`|`no_sale`|`price_edit`|`stamp_adjust`…) · employee_id · من أذن · السبب · قيمة · الوقت · order_id.

**الجرد `stock_counts`:** material_id · متوقّع · معدود · الفرق% · الوقت.

**الزبائن `customers`:** id · الهاتف (مفتاح) · الاسم · تاريخ أول زيارة.
**الأختام `stamps`:** customer_id · order_id · الوقت (كل صف = ختم واحد من بيع مسجّل).
**الصرف `redemptions`:** customer_id · order_id · الوقت (مشروب مجاني صُرف).

## ٢) منطق البيع (تدفّق)
1. الباريستا يدخل برمزه → وردية مفتوحة.
2. يضيف مشروبات (+تعديلات) → طلب `open`، يظهر مبلغه الحالي **فقط**.
3. زبون (اختياري): **يمسح QR ويُدخل رقمه بنفسه** (يُقصي الباريستا عن الولاء).
4. الدفع: **كاش** (يُدخل المبلغ → الباقي) أو **بطاقة** (زرّ فقط — جهاز البنك يأخذ الفلوس).
5. عند الدفع: الحالة `paid` → **خصم المخزون** (§٤) → **منح ختم** إن وُجد زبون ومشروب مؤهّل (§٧) → طبع فاتورة.
- **قاعدة:** لا يُقدَّم مشروب بلا طلب `paid` (والمخزون هو من يكشف المخالف — §٥).

## ٣) منطق الدفع
- كاش: يزيد «الدرج المتوقّع» للوردية.
- بطاقة: لا يمسّ الدرج (الفلوس بحساب المالك). يُخزَّن كـ`card` للمقارنة (§٨).

## ٤) خصم المخزون
عند `paid`: لكل بند → لكل مادة في وصفته → **أنقص (الكمية × كمية الوصفة)** من `materials.stock`.
- المشروب المجاني (ولاء) **يُخصم أيضاً** (سعره صفر، لكن المواد تنقص).
- الهدر (§زرّ) ينقص المخزون بسببه.

## ٥) الجرد والفرق (كشف سرقة «ب»)
- **الاستهلاك النظري** لكل مادة خلال المدة = Σ(الوصفة × المبيعات) + Σ(الهدر المسجّل).
- **الفعلي** = مخزون بداية − مخزون معدود نهاية.
- **الفرق% = (فعلي − نظري) ÷ نظري**.
- **قاعدة الإنذار:** فرق% > **٢–٣٪ (تأكيد)** → تحقيق. الكوب مرجع (هدره ~صفر؛ أي فرق كوب = علم أحمر).

## ٦) الوردية والدرج
- بداية: فكّة افتتاحية.
- **الدرج المتوقّع = الفكّة + مبيعات الكاش − إرجاعات الكاش**.
- نهاية: الباريستا **يُدخل المعدود بلا رؤية المتوقّع (عدّ أعمى)** → النظام يحسب زيادة/نقص → `audit_log`. نقص متكرّر = إنذار.

## ٧) منطق الولاء
**المنح (earn):**
- عند `paid` + زبون موجود: كل بند **مشروب مؤهّل** = ختم واحد (لكل مشروب).
- **سقف أختام للفاتورة الواحدة = N (تأكيد، مثلاً ٤)** — ضدّ الطلب الجماعي.
- المنيو الأغلى: `مؤهّل_للولاء = false` → لا ختم.
- الختم **يأتي من بيع مسجّل فقط** — لا زرّ ختم يدوي (يقفل الأختام الوهمية).

**الصرف (redeem):**
- عند **٥ أختام** → المشروب التالي المؤهّل **مجاني** (بند سعره صفر) → تُستهلك ٥ أختام (`redemptions`) → المخزون ينقص (§٤).
- **قيمة المجاني بحدّ مشروب عادي (تأكيد)** — لو صرفه على أغلى، يدفع الفرق.

**الانتهاء:** أختام تخمل **٣ شهور (تأكيد)** تسقط (تقلّل الالتزام + سبب رسالة استرجاع).

**ضبط الاحتيال:**
- **التسجيل الذاتي بالـQR** (الباريستا خارج الولاء).
- **سقف سرعة:** أختام حساب واحد/يوم > حدّ (تأكيد، مثلاً ١٠) → إنذار.
- تعديل الأختام يدوياً = صلاحية مالك + `audit_log`.
- الزبون يرى رصيده بالرابط = شاهد.

## ٨) الصلاحيات والتقرير الاستثنائي
**يحتاج إذن مالك (PIN) + سبب + `audit_log`:** إلغاء بعد الدفع · إرجاع · خصم/مجاني يدوي · فتح درج بلا بيع · تعديل سعر/منتج/وصفة · تعديل أختام · رؤية تقارير.
**مسموح للباريستا (يُسجَّل):** تصحيح قبل الدفع · هدر بسبب · فتح درج مع بيع.
**قواعد العلم الأحمر (exceptions):** نسبة إلغاء عالية لموظف · إلغاء بعد الدفع · إلغاء وقت الهدوء/قبل الطبع · فرق إلغاء كاش‑مقابل‑بطاقة · نقص درج · قفزة فرق مخزون · مجاني كبير.

## ٩) الرؤية
- **باريستا:** طلبه الحالي ومبلغه · أزرار المشروبات · هدر · فتح/إغلاق وردية (عدّ أعمى). **لا أرقام تراكمية ولا تقارير.**
- **مالك:** لمحة اليوم · التقرير الاستثنائي · الفروقات · جرد الكاش · مراقبة الولاء (أعلى الجامعين/الصرف/السرعات) · أداء كل باريستا · تحليلات. **الافتراضي = الشاذّ + تنبيهات موبايل.**

## ١٠) المشروب ↔ المحصول
`drinks.crop` يربط المشروب بحبوب معيّنة → يخدم: خصم المخزون الصحيح · التوصية · تحليلات المحصول.

## القرارات المطلوب تأكيدها قبل البناء
1. مل الحليب لكل مشروب (لاتيه/كابتشينو/…).
2. سقف الأختام للفاتورة الواحدة.
3. قيمة المشروب المجاني: بحدّ العادي أم أي نوع.
4. حدّ سرعة الأختام اليومي.
5. مدّة انتهاء الأختام.
6. عتبة إنذار الفرق% (٢ أم ٣٪).
7. قائمة «المنيو الأغلى» المستثنى.

## مراحل البناء (مقترحة)
1. **الأساس:** مشروبات + مواد + وصفات + شاشة بيع + دفع + طباعة.
2. **المخزون:** خصم تلقائي + هدر + جرد + فرق.
3. **الموظف والأمان:** رمز دخول + صلاحيات + ورديات + درج + تقرير استثنائي + تنبيهات.
4. **الولاء:** QR تسجيل ذاتي + منح/صرف + رابط الزبون + ضبط الاحتيال.
5. **التحليلات** ولمسات.
