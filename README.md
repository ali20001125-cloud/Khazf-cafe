# كاشير خزف

نظام كاشير مقهى + ولاء. **مشروع منفصل تماماً عن موقع خزف.**
Next.js + Supabase · عربي · RTL.

المواصفات الكاملة في `docs/CAFE-POS-LOGIC.md` (منطق العمل) و `docs/CAFE-POS-PLAN.md` (الخلفية والقرارات).

---

## الحالة: المرحلة ١ مكتملة

| | |
|---|---|
| ✅ المشروبات | إضافة/تعديل/تعطيل · فئة · سعر · محصول · مؤهّل للولاء |
| ✅ المواد الخام | غرام / مل / حبة · مخزون · حد تنبيه |
| ✅ الوصفات | مادة + كمية لكل مشروب · «للسفري فقط» للكوب والغطاء |
| ✅ شاشة البيع | شبكة كبيرة · سفري/جلوس · شوت إضافي · سلة |
| ✅ الدفع | كاش (مبلغ مستلم + باقي) · بطاقة (زرّ فقط، بلا بوابة دفع) |
| ✅ الفاتورة | طباعة حرارية ٨٠مم من المتصفح |
| ✅ خصم المخزون | تلقائي وذرّي عند كل بيع مدفوع |

**المراحل القادمة:** ٢ الجرد والفرق والهدر · ٣ الموظفون والورديات والدرج والتقرير الاستثنائي · ٤ الولاء · ٥ التحليلات.
جداول كل المراحل موجودة في المخطّط من الآن حتى لا نكسره لاحقاً.

## التشغيل

```bash
npm install
cp .env.example .env.local     # املأ القيم
npm run dev
```

### إعداد Supabase

من محرّر SQL في لوحة Supabase، شغّل بالترتيب:

1. `supabase/migrations/0001_init.sql` — الجداول والأنواع و RLS
2. `supabase/migrations/0002_checkout.sql` — دالة إتمام البيع
3. `supabase/seed.sql` — منيو ومواد ووصفات مبدئية (اختياري)

### المتغيّرات

| المتغيّر | الوصف |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | رابط مشروع Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | مفتاح الخادم — **لا يُكشف للمتصفح أبداً** |
| `ADMIN_PIN` | رمز لوحة المالك (مؤقّت للمرحلة ١) |

## الأمان

- **RLS مقفلة بالكامل** على كل الجداول (`enable` + `force`)، **وبلا أي سياسة عامة**.
  مفتاح `anon` لا يقرأ ولا يكتب أي شيء حتى لو تسرّب.
- كل وصول لقاعدة البيانات يمرّ من خادم Next.js بمفتاح `service_role`.
  `src/lib/supabase.ts` معلَّم `server-only` — استيراده في مكوّن متصفح يفشل البناء.
- **الأسعار تُحسب داخل قاعدة البيانات**، لا من المتصفح. لو عبث أحد بالطلب المرسل،
  السعر يبقى سعر الجدول.
- البيع **عملية ذرّية واحدة**: الطلب والبنود وخصم المخزون معاً، أو لا شيء.
- **أرقام الفواتير بلا فجوات**: رقم الفاتورة يُسحب بعد نجاح كل التحقّق،
  فالمحاولة الفاشلة لا تحرق رقماً. أي فجوة لاحقاً تعني شيئاً يستحق السؤال.
- تعديل الأسعار والوصفات يُسجَّل في `audit_log`.
- **زرّ «بطاقة» يسجّل فقط** — لا بوابة دفع ولا بيانات بطاقات في النظام.

## «الأرقام السبعة» — القيم الحالية

القيم أدناه **افتراضات مبدئية** موضوعة حتى يعمل النظام، وكلها تُعدَّل من
`/admin/settings` أو من محرّر الوصفات بلا نشر كود. المرحلة ١ لا تتأثر إلا
بالرقمين ١ و ٧؛ البقية تخصّ مراحل لاحقة.

| # | القرار | القيمة الحالية | أين تُعدَّل |
|---|---|---|---|
| ١ | مل الحليب لكل مشروب | لاتيه ١٨٠ · كابتشينو ١٥٠ · فلات وايت ١٥٠ · موكا ١٨٠ · آيس لاتيه ٢٠٠ | `/admin/drinks/[id]` |
| ٢ | سقف الأختام للفاتورة | ٤ | `/admin/settings` |
| ٣ | قيمة المشروب المجاني | بحدّ ٣٠٠٠ (سعر مشروب عادي) والفرق يدفعه الزبون | `/admin/settings` |
| ٤ | حدّ سرعة الأختام اليومي | ١٠ | `/admin/settings` |
| ٥ | مدّة انتهاء الأختام | ٩٠ يوماً | `/admin/settings` |
| ٦ | عتبة إنذار الفرق | ٣٪ | `/admin/settings` |
| ٧ | «المنيو الأغلى» المستثنى | في٦٠ · تقطير (`loyalty_eligible = false`) | `/admin/drinks` |

الأسعار في `supabase/seed.sql` بالدينار العراقي وهي أمثلة — بدّلها بأسعارك.

## الطباعة

الفاتورة تُطبع من المتصفح على حرارية ٨٠مم عبر `@page { size: 80mm auto }`.
تُفتح نافذة الطباعة تلقائياً بعد كل بيع.

**عند شراء الطابعة:** اضبطها طابعة افتراضية في المتصفح وفعّل الطباعة الصامتة
(في Chrome: `--kiosk-printing`) حتى تخرج الفاتورة بلا نافذة تأكيد.
