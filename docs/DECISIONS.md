# قرارات المشروع

سجلّ ما حُسم وما بقي مفتوحاً. يُحدَّث مع كل قرار جديد حتى لا يضيع بين الجلسات.

---

## مبادئ ثابتة

1. **باك إند قوي، فرونت إند بسيط.** المنطق والتحقّق والحساب كلها في الخادم وقاعدة
   البيانات. الواجهة تعرض وتلمس فقط. لو تعارض «أبسط للواجهة» مع «أمتن للخادم»،
   يفوز الخادم.
2. **شاشة الباريستا للاستخدام اليومي.** أقل ضغطات ممكنة، أزرار كبيرة، بلا شاشات
   تعليمية. السرعة شرط أمني: شاشة بطيئة تدفع الباريستا لتجاوز التسجيل.
3. **مشروع منفصل تماماً عن موقع خزف.** كود منفصل، قاعدة بيانات منفصلة، مفاتيح
   منفصلة. الربط بعالم خزف يأتي لاحقاً عبر رقم الهاتف إن أُريد.
4. **الكشف قبل المنع.** المالك غائب غالباً، فنسجّل كل شيء بسببه ونراجع، بدل
   أقفال صارمة تعطّل العمل.

## قرارات محسومة

| القرار | الحسم |
|---|---|
| الستاك | Next.js + **Neon Postgres 17** |
| قاعدة البيانات | مشروع Neon **`khazf-cafe`** — منفصل تماماً عن قاعدة المتجر الأونلاين |
| المنطقة | **فرانكفورت `aws-eu-central-1`** — الأقرب للعراق |
| لماذا لا Supabase | الخطة المجانية تسمح بمشروعين لكل مالك حساب، وكلاهما مستهلك للموقع. وNeon أنسب أصلاً: بلا واجهة قاعدة بيانات عامة |
| العملة | الدينار العراقي، أعداد صحيحة بلا كسور |
| الدفع | كاش وبطاقة. **لا بوابة دفع** — زرّ «بطاقة» يسجّل فقط |
| الطابعة | حرارية ٨٠مم، طباعة من المتصفح |
| **دورات الجرد** | **يومي + أسبوعي + شهري** (ثلاث دورات معاً، لكل واحدة عتبة إنذار مختلفة) |
| الولاء | مربوط بالكاشير، ختم من بيع مسجّل فقط، تسجيل الزبون ذاتي بالـQR |
| الوصول لقاعدة البيانات | من الخادم فقط برابط اتصال سرّي · لا واجهة عامة ولا مفتاح مجهول |

## مفتوح

- النشر: الكاشير غير منشور حالياً. المالك سينشره لمعاينته حيّاً.
- النسخ الاحتياطي: يُحسم عند الافتتاح الفعلي. نظام فلوس بلا نسخة احتياطية مخاطرة.
- ثغرة مفتوحة في قاعدة الموقع (مشروع Supabase الهندي): ١٠ جداول عليها RLS مطفأة
  ومكشوفة لمفتاح anon، منها `otp_codes` و `wholesale_customers` و `wholesale_payments`.
  خارج نطاق هذا المشروع لكنها تحتاج معالجة.
- الضريبة على الفاتورة: غير محسوم إن كانت مطلوبة.
- وضع «عدم الاتصال» (offline): مؤجّل، لكن التعامل مع انقطاع الشبكة أثناء الدفع
  مطلوب قبل التشغيل اليومي.

## إعادة البناء (سبتمبر ٢٠٢٦)

المحاولة الأولى كانت مخطّطاً مبسّطاً (مخزون قابل للتعديل مباشرة، بلا دفتر حركات،
بلا سعر لكل محصول، بلا منع تكرار الدفع). أُعيد بناء المخطّط بالكامل ليطابق المواصفة
التقنية **`CAFE-POS-TECH.md`** — وهي المرجع الوحيد الآن — لأن أعمدة منع السرقة
(دفتر `inventory_transactions` غير القابل للتعديل · سعر لكل محصول في `product_crops` ·
منع الدفع المكرّر بـ`idempotency_key` · `cash_movements` · `day_closes` · لقطة الوصفة)
جوهرية لا تُضاف على مخطّط قديم. حُذف كود التطبيق القديم (كان يخاطب المخطّط القديم)
ويُعاد بناؤه مرحلة‑مرحلة على المخطّط الجديد. `db/migrations/0001_schema.sql` هو المخطّط
المعتمد، و`db/seed.sql` البذور. طُبِّقا على قاعدة Neon الحيّة وتُحقِّق من سلامتهما
(الرصيد = مجموع الدفتر، وتهشير PIN متوافق مع bcryptjs).

## حالة البناء (خطة الـ٨ مراحل)

- ✅ **م٠ حجر الأساس** — المخطّط (٢٤ جدولاً مطابقاً للمواصفة) · البذور (عمل/فرع/أدوار/
  مستخدمَين/مواد/مشروبات/محاصيل/وصفات/إعدادات + رصيد افتتاحي عبر الدفتر) · إعداد المشروع
  (Next 14.2.35 بعد ترقية أمنية · `db.ts`/`format.ts`/`types.ts`/`settings.ts` · صفحة
  رئيسية متصلة بالقاعدة) · البناء يمرّ بلا أخطاء (`typecheck` + `build`).
- ⬜ **م١ الدخول والصلاحيات** — PIN (bcrypt + حدّ محاولات) · جلسة · فحص صلاحيات خادمي.
- ⬜ **م٢ شاشة البيع** — شبكة المشروبات · اختيار المحصول · بناء الطلب DRAFT.
- ⬜ **م٣ الدفع الذرّي** — `checkout()` بمعاملة واحدة · idempotency · قفل الصفوف · خصم الدفتر · فاتورة.
- ⬜ **م٤ الورديات والدرج** — فتح/إغلاق · عدّ أعمى · فرق · حركات كاش · إغلاق اليوم.
- ⬜ **م٥ المخزون** — شراء · هدر · جرد أعمى (COUNT ثم ADJUSTMENT) · كشف فرق%.
- ⬜ **م٦ لوحة المالك** — لمحة اليوم · الشاذّ · الفروقات · الموافقات · القفل الطارئ.
- ⬜ **م٧ اللمسات** — اختبارات (فلوس/مخزون/صلاحيات) · تغطية التدقيق · النشر.

*(الولاء والتجزئة وتعدّد الفروع = V2، خطاطيف جاهزة في المخطّط.)*

## ملاحظات تقنية مثبّتة

- **الاتصال بـNeon من بيئة التطوير:** عبر أدوات Neon (HTTP API). اتصال Postgres الخام
  (منفذ 5432) عبر `psql` محجوب ببروكسي البيئة — تُطبَّق الهجرات بـ`run_sql_transaction`.
- **ترقية Next.js:** رُفع إلى 14.2.35 (سدّ ثغرة حرجة). ثغرات DoS متبقية حلّها الانتقال
  إلى Next 16 (تغيير جذري) — مؤجّل لمهمة مستقلة؛ الكاشير داخلي لا عام فالتعرّض محدود.
- **تهشير PIN:** بذور Neon تولّده بـpgcrypto `crypt(pin, gen_salt('bf'))` = bcrypt `$2a$`
  يتحقّق منه التطبيق بـ`bcryptjs` (م١).
- **أرقام دخول افتراضية في `db/seed.sql`** ضعيفة عمداً وتُغيَّر فور أول تشغيل من اللوحة.
