# خزف كافيه — نظام الكاشير والمخزون

كاشير مقهى بسيط للواجهة، متين في الخلفية: يمنع السرقة عبر دفتر مخزون غير قابل
للتعديل، دفع ذرّي، عدّ درج أعمى، وصلاحيات مفروضة في الخادم. الأرقام إنجليزية،
والفلوس بالدينار العراقي بلا كسور. **مشروع منفصل تماماً عن موقع خزف.**

المواصفة المرجعية: **`docs/KHAZAF-POS-TECHSPEC.md`** (٢٠ قسماً: المخطّط · القيود ·
آلات الحالة · صيغ الكاش · نقاط النهاية · المعاملات · منع التكرار · التدقيق ·
الاختبارات · اختبارات الأمن). القرارات: `docs/DECISIONS.md`.
`docs/CAFE-POS-TECH.md` مواصفة V1 السابقة، تبقى للسياق التاريخي.

## التقنية
- Next.js 14 (App Router) · React 18 · TypeScript · Tailwind.
- Neon Postgres 17 — الوصول من الخادم فقط برابط سرّي (لا واجهة عامة، لا مفتاح مجهول).
- منطق المال والمخزون في **دوال قاعدة** ذرّية (`db/migrations`).

## التشغيل محلياً
```bash
npm install
cp .env.example .env.local   # واملأ القيم
npm run dev
```

## المتغيّرات (`.env.local`)
| المتغيّر | الوصف |
|---|---|
| `DATABASE_URL` | رابط Neon (سرّي، بلا `NEXT_PUBLIC_`) |
| `SESSION_SECRET` | سرّ توقيع الجلسة — ولّده: `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"` |

## قاعدة البيانات
طبّق بالترتيب (تفاصيل وتحذيرات في `db/README.md`):
1. `0001_schema.sql` … `0008_perms.sql` — المخطّط والدخول والدفع والمخزون والخيارات.
2. `db/seed.sql` ثم `db/seed-modifiers.sql` — بيانات أوّلية.
3. `0009_permissions_v2.sql` — كتالوج الصلاحيات المنقّطة.
4. `0010_enums.sql` — توسيع الأنواع. **جملة‑جملة، خارج معاملة واحدة.**
5. `0011_integrity.sql` — الدفتر للإلحاق فقط · حارس الرصيد · آلات الحالة · قفل اليوم.
6. `0012_orders_v2.sql` — تاريخ الأسعار · الخصومات · الإلغاء · الإرجاع.
7. `0013_cash_v2.sql` — فتح الدرج بلا بيع · تسليم الدرج · الإغلاق الأعمى.
8. `0014_loyalty.sql` — الولاء كاملاً (OTP · دفتر · مكافآت · صرف).
9. `0015_checkout_v3.sql` — البيع v3. **لا يُفصَل عن 0011** وإلا خُصم المخزون مرّتين.
10. `0016_reports.sql` — الفروقات ولوحات المالك والاستثناءات.

## النشر (Vercel)
1. اربط المستودع بمشروع Vercel.
2. أضف `DATABASE_URL` و`SESSION_SECRET` في إعدادات البيئة.
3. طبّق الهجرات والبذور على قاعدة Neon (مرّة واحدة).
4. انشر. (بيئة التطوير هنا لا تصل Neon بسبب حجب الشبكة — الاختبار الحيّ بعد النشر.)

**الطابعة الحرارية:** الفاتورة تُطبع من المتصفح (٨٠مم). عند الشراء اجعلها الافتراضية
وفعّل الطباعة الصامتة (Chrome: `--kiosk-printing`) لتخرج بلا نافذة تأكيد.

## أرقام الدخول الافتراضية — **غيّرها فوراً**
- المالك: `1111` · الباريستا: `0000` (في `db/seed.sql`). ضعيفة عمداً للتجربة فقط.

## مبادئ معمارية (لا تُكسَر)
- **الرصيد = Σ(inventory_transactions)**؛ `cached_stock` تسريع، **كاتبه الوحيد
  مُشغّل الدفتر** — أي تعديل مباشر يُرفَض في القاعدة.
- **الدفاتر للإلحاق فقط**: المخزون · التدقيق · الكاش · الولاء — لا تعديل ولا حذف.
- **آلات الحالة مفروضة بمُشغّلات**: الطلب · الدفع · مكافأة الولاء · تسليم الدرج.
- **الدفع ذرّي**: طلب + مخزون + كاش في معاملة واحدة، مع منع تكرار (`idempotency_key`)
  وقفل صفوف يمنع المخزون السالب. رقم الطلب بعد التحقّق → بلا فجوات.
- **الأسعار تُحسب في القاعدة** لا من المتصفح.
- **الصلاحيات تُفحص في الخادم** لكل عملية (لا يكفي إخفاء الزر ولا فحص الـlayout —
  الـServer Actions تُنادى بطلب مباشر).
- **لا حذف** للعمليات المالية/المخزنية — التصحيح بعملية عكسية.
- عدّ الدرج والجرد **أعميان** (كشف النقص). `src/lib/db.ts` معلَّم `server-only`.

## الحالة
مراحل م٠–م٧ منجزة (V1)، وطبقة المواصفة الكاملة (`0009`–`0016`) **مطبَّقة على قاعدة
Neon الحيّة** ومُختبَرة (§19 من المواصفة التقنية).

**الواجهات المبنيّة فوقها:**
- **الولاء كاملاً**: صفحة تسجيل الزبون الذاتي (`/loyalty`) · ربط العميل بالفاتورة
  من شاشة البيع · صرف المكافأة كطلب مستقلّ بإجمالي صفر.
- **الإلغاء والإرجاع** (`/manage/orders`) برمز المالك، مع سقف إرجاع مفروض في القاعدة.
- **لوحة الشاذّ** (`/manage/exceptions`) — فروقات الدرج والمخزون بمكافئ الجرعات،
  والإلغاءات والإرجاعات وفتح الدرج بلا بيع.

**المتبقّي:** مزوّد رسائل الواتساب لإرسال رمز التحقّق (الرمز يُسجَّل خادمياً حتى
يُحسم المزوّد) · شاشة الخصم · فتح الدرج بلا بيع وتسليم الدرج في شاشة الباريستا.
