# قاعدة البيانات — خزف كافيه

المرجع الكامل للمخطّط والقيود: **`docs/KHAZAF-POS-TECHSPEC.md`** (يحلّ محلّ
`CAFE-POS-TECH.md` الذي يبقى للسياق التاريخي).

## الملفات
- `migrations/0001_schema.sql` — المخطّط الأساس (٢٨ جدولاً بعد 0006، أنواع، فهارس، قيود).
- `migrations/0002`–`0008` — الدخول · الدفع · المخزون · مشروب الموظف · الخيارات · دفع v2 · صلاحيات.
- `migrations/0009`–`0016` — طبقة المواصفة الكاملة (صلاحيات منقّطة · تكامل · طلبات v2 ·
  كاش v2 · ولاء · بيع v3 · تقارير).
- `migrations/0017`–`0022` — تصحيحات بعد التجربة الحيّة:
  - `0017_business_day` — اليوم المحاسبي يبدأ الساعة ٥ لا منتصف الليل، فوردية
    تُغلق فجراً لا تنقسم بين يومين.
  - `0018_remove_extra_shot` — تعطيل «الشوت الإضافي» (لا حذف).
  - `0019_settings_consolidation` — الفكّة وعتبة الفروقات في `branches` وحدها.
  - `0020_inventory_overview` — `material_overview()`: تراكمي، مع معدّل يومي وأيام متبقّية.
  - `0021_void_cash` — إلغاء فاتورة مدفوعة يسأل **هل أُعيد المال؟** ويكتب حركة
    عكسية عند «نعم». بدونها يظهر نقص كاذب على باريستا أمين.
  - `0022_dose_from_recipe` — `material_dose()` تشتقّ الجرعة من الوصفة، ونقصٌ
    يعادل مشروبين فأكثر أحمر مهما صغرت نسبته.
  - `0023_user_pins` — `users.pin_changed_at`. فراغه = الرمز ما زال افتراضياً،
    فيظهر تحذيراً أحمر لا يزول إلا بالتغيير.
  - `0024_cogs` — **ختم التكلفة لحظة الاستهلاك** + `v_order_cogs` و`day_profit()`
    و`product_profit()`. الربح من تكلفة يوم البيع، فلا يتبدّل إذا غلا سعر اليوم.
- `seed.sql` · `seed-modifiers.sql` — بيانات أوّلية قابلة للتعديل من اللوحة.

## ترتيب التطبيق
1. `0001_schema.sql`  (يبدأ بإسقاط نظيف — آمن لإعادة التطبيق على قاعدة تطوير).
2. `0002` … `0008` بالترتيب.
3. `seed.sql` ثم `seed-modifiers.sql`.
4. `0009` … `0024` بالترتيب.

### تحذيران عند تطبيق 0009–0016
- **`0010_enums.sql` يُطبَّق جملة‑جملة، خارج معاملة واحدة.** Postgres يسمح بإضافة
  قيمة لنوع enum داخل معاملة لكنه يمنع استخدامها في نفس المعاملة.
- **`0011` و`0015` توأمان.** بعد 0011 صار مُشغّل الدفتر هو الكاتب الوحيد لـ
  `cached_stock`، و0015 يحذف التحديث اليدوي من دوال البيع. تطبيق 0011 وحده =
  **خصم مزدوج للمخزون**.

الهجرات كلّها **قابلة لإعادة التطبيق** (idempotent) وقد جُرِّبت كذلك.

## كيف تُطبَّق
- **من بيئة التطوير هنا:** أدوات Neon (`run_sql_transaction`) عبر HTTP API — لأن
  اتصال Postgres الخام (منفذ 5432) محجوب ببروكسي البيئة.
- **محلياً بجهازك:** `psql "$DATABASE_URL" -f db/migrations/0001_schema.sql`
  ثم `psql "$DATABASE_URL" -f db/seed.sql`.

## مبادئ لا تُكسَر
- الرصيد الحقيقي للمخزون = `Σ(inventory_transactions.qty_delta)`.
  `materials.cached_stock` تسريع فقط. **بعد 0011 صار هذا مفروضاً في القاعدة:**
  مُشغّل الدفتر هو كاتبه الوحيد، وأي `update materials set cached_stock` يُرفَض.
- الفلوس والكميات أعداد صحيحة.
- لا حذف للعمليات المالية/المخزنية — التصحيح بعملية عكسية. مفروض بمُشغّلات
  «للإلحاق فقط» على `inventory_transactions` و`audit_log` و`cash_movements`
  و`loyalty_ledger`، وبمنع حذف/تعديل `payments`.
- آلات الحالة (الطلب · الدفع · المكافأة · تسليم الدرج) مفروضة بمُشغّلات، لا بالكود.
