# خزف كافيه — كاشير + مخزون · خطة العمل ومواصفات البناء (V1)

> **الغرض:** الأساس النهائي للبناء — كل قاعدة ومسار مكتوب هنا حتى لا نخترع قرارات أثناء البرمجة.
> **يُقرأ مع** `CAFE-POS-PLAN.md` و`CAFE-POS-LOGIC.md` (خلفية النقاش) — وهذا الملف هو **المرجع الأحدث والأشمل**.
> **مشروع منفصل:** مستودع `khazf-cafe` · قاعدة **Neon (Postgres)** · Next.js + TypeScript + Tailwind + Drizzle.
> **الحالة:** مواصفات جاهزة للبناء. لم يبدأ الكود.

## ٠) المبدأ الحاكم
**POS سريع للباريستا + لوحة للمالك + قاعدة محاسبية لا يُمحى منها التاريخ.**
- **التعقيد بالخلفية، والواجهة سهلة:** لغة عربية بسيطة قصيرة · أرقام **إنجليزية** · الخلفية تسوّي كل الحساب · لا مصطلحات محاسبية/تقنية للمستخدم.
- المالك **ليس محاسباً**، والباريستا **ليس كاشيراً** — النظام موجّه لهما.

## ١) الأدوار والصلاحيات
- **Owner (المالك):** كل شيء.

- الآن: Owner=كل الصلاحيات · Barista=`sell` فقط (+ هدر/مشروب موظف/فتح‑إغلاق وردية). الباقي يحتاج موافقة المالك.
- القاعدة **جاهزة** لأدوار أكثر (Manager/Cashier) وفروع أكثر بلا إعادة بناء.

## ٢) المبادئ الهندسية (إلزامية — غير قابلة للتفاوض)
1. **Immutable Ledger:** لا حذف/تعديل لأي عملية مالية أو مخزنية. التصحيح = **عملية عكسية** (Void/Refund/Adjustment) والأصل يبقى.
2. **Atomic:** الدفع + تعليم الطلب مدفوعاً + خصم المخزون = **معاملة واحدة**؛ كلها تنجح أو كلها تفشل. ممنوع «دفع نجح ومخزون ما نقص».
3. **Backend Permissions:** كل عملية حسّاسة تُفحص صلاحيتها في الخادم (حتى لو نُودي الـAPI مباشرة).
4. **Audit Log:** كل عملية حسّاسة → من/ماذا/متى/قبل/بعد/السبب. لا تُمحى.
5. **وقت السيرفر** لكل الطوابع الزمنية (لا ساعة جهاز الباريستا).
6. **Idempotency:** ضغط «دفع» مرتين ≠ دفعتين/خصمين. كل عملية حسّاسة تحمل مفتاحاً فريداً.
7. **منع المخزون السالب:** لا بيع لمشروب لا تكفي مواده. المحصول الفارغ يختفي.
8. **إعادة التحقق وقت الدفع:** يُتحقق من كفاية المخزون **لحظة الدفع** لا لحظة إضافة المنتج.
9. **تجميد اللقطة (Snapshot):** كل بند طلب يحفظ **سعره ووصفته وقت البيع**؛ تغيير السعر/الوصفة لاحقاً لا يمسّ الطلبات القديمة.
10. **العدّ الأعمى:** الباريستا يُدخل الكاش المعدود **قبل** رؤية المتوقّع.
11. **قيود القاعدة (Data Integrity):** القاعدة نفسها تمنع الخطأ:
    لا طلب بلا فرع · لا دفع بلا طلب · لا بند بلا منتج · لا حركة مخزون بلا سبب · **لا إرجاع أكبر من المدفوع** · لا رقم طلب مكرّر · لا كمية سالبة حيث تُمنع · لا ورديتان متداخلتان لنفس الدرج.

## ٣) نموذج البيانات — V1 (~15 كيان أساسي)
> كل الجداول التشغيلية تحمل `business_id` و`branch_id` (خطاطيف التوسّع؛ فرع واحد الآن).

- **businesses** · **branches** (اسم · إعدادات · فكّة قياسية).
- **users:** اسم · دور · `pin_hash` (لا نصّ صريح) · نشط.
- **products (المشروبات):** اسم · فئة · نشط/موقوف · حدّ يومي اختياري · مشروب اليوم (علم).
- **product_crops (محاصيل المشروب + سعره):** product · material(الحبوب) · **السعر لهذا المحصول** · متاح.
- **materials (المواد):** اسم · وحدة أساس (`g`/`ml`/`pcs`) · حدّ تنبيه منخفض · التكلفة الحالية (متوسط مرجّح).
- **recipes / recipe_items:** لكل مشروب (وحجم لاحقاً) → مواد + كميات. **مرقّمة نسخاً (versioned)**.
- **inventory_transactions (Ledger):** النوع (`PURCHASE`/`SALE`/`WASTE`/`STAFF`/`ADJUSTMENT`/`COUNT`) · material · كمية(±) · تكلفة · السبب · order_id · user · وقت. **الرصيد = مجموع الحركات** (مع رصيد مشتَق مخزّن للسرعة، يتغيّر فقط بحركة).
- **orders:** `order_number`(مقروء، من 1001) · branch · shift · employee · الحالة · طريقة الدفع · الإجمالي · أوقات. + `customer_id` **اختياري** (للولاء لاحقاً).
- **order_items:** product · crop · (حجم لاحقاً) · **سعر مجمّد** · **لقطة وصفة**.
- **payments:** order · طريقة · المبلغ · **المدفوع (tendered)** · **الباقي (change)** · مرجع البطاقة(اختياري) · الحالة.
- **shifts:** employee · branch · **فكّة البداية** · وقت فتح/إغلاق · متوقّع/معدود · الفرق.
- **cash_movements:** النوع (`OPENING`/`SALE`/`REFUND`/`EXPENSE`/`DROP`/`REMOVAL`) · المبلغ(±) · السبب · user · وقت.
- **waste:** material · كمية · السبب · user · وقت.
- **staff_drinks:** drink · crop · user · shift · وقت.
- **audit_log** · **settings**.

*(مؤجّل مع خطاطيف القاعدة: customers/loyalty · retail bags · suppliers · batches · stock_transfers · devices.)*

## ٤) دورات الحياة (State Machines)
- **الطلب:** `DRAFT → PAID → COMPLETED` · واستثناءً `VOIDED` / `REFUNDED`. (V1: PAID تُعامل COMPLETED فوراً؛ حالات التحضير لاحقاً.)
- **الدفع:** `PENDING → CONFIRMED` أو `FAILED`. المخزون يُخصم **فقط عند CONFIRMED** (ضمن Atomic). عند فشل/انقطاع → لا CONFIRMED، لا خصم، رسالة «انقطع الاتصال».
- **الوردية:** `OPEN → CLOSED` (الإغلاق يتطلّب العدّ الأعمى). **اليوم:** كل الورديات مغلقة → `DAY_CLOSED` (يقفل تعديل عمليات اليوم).
- **المخزون:** الرصيد من الحركات فقط؛ لا تعديل مباشر — التصحيح `ADJUSTMENT` بسبب.

## ٥) المسارات (Workflows) — بدقّة

### ٥.١ فتح الوردية
دخول بالـPIN → إدخال **فكّة البداية** (المبلغ الفعلي، حرّ لكل يوم) → تأكيد → الوردية `OPEN` + حركة `OPENING`.

### ٥.٢ البيع
اختيار مشروب → **اختيار المحصول** (تلقائي لو محصول واحد · يُجبر لو متعدّد، وكل محصول بسعره) → إضافات (المؤثّرة على السعر/الوصفة تُحسب؛ سكر مجاني بلا حساب) → **سفري/جلوس** (يؤثّر على خصم الكوب) → يُضاف للطلب الحالي (**بلا خصم مخزون بعد**) → تكرار · **طلبات مفتوحة** (يعلّق ويرجع، محفوظة بالقاعدة تصمد لو انطفى الجهاز).

### ٥.٣ الدفع
اختيار **كاش/بطاقة**.
- **كاش:** السعر يظهر تلقائياً → يُدخل **المبلغ المدفوع** → النظام يطلّع **الباقي** → تأكيد.
- **بطاقة:** الإجمالي فقط (+ مرجع اختياري). جهاز البنك منفصل.
- عند التأكيد (**Atomic**): Payment `CONFIRMED` + Order `PAID` + **خصم المخزون** (وصفة المحصول المختار) + الدرج `+SALE` (بقيمة البيع) + طباعة **عند الطلب** + نبضة فتح الدرج (كاش فقط).

### ٥.٤ الهدر
زرّ هدر → مادة → كمية → **سبب** (سكب/تحضير خاطئ/تلف/انتهاء/تنظيف/آخر) → حفظ → مخزون `−` + سجل. *(هدر كبير فوق حدّ → يحتاج موافقة المالك.)*

### ٥.٥ مشروب الباريستا
زرّ مشروب موظف → مشروب + محصول → تأكيد → سعر 0 + خصم مخزون + سجل. **حدّ 1/وردية؛ الثاني بموافقتك.** منفصل عن الهدر والمبيعات.

### ٥.٦ سحب كاش (اختياري)
مبلغ + سبب → حركة `DROP`/`REMOVAL` `−` + سجل → المتوقّع بالدرج ينقص.

### ٥.٧ إلغاء / إرجاع / خصم
- **تصحيح قبل الدفع (Void draft):** يُشيل بند/طلب، بلا خسارة، يُسجَّل.
- **إلغاء بعد الدفع / إرجاع / خصم:** **بموافقة المالك** (تُفحص بالخادم) + سبب إجباري + **سجل موافقات** (طلبها/وافق/الوقت/السبب). الإرجاع = فلوس فقط، **المواد لا ترجع**. الأصل يبقى، ونضيف عملية عكسية.
- **خصم:** الباريستا **لا يخصم** (أسعار ثابتة). أي خصم = من المالك.

### ٥.٨ إغلاق الوردية
زرّ إغلاق → **عدّ أعمى** (يُدخل الكاش المعدود) → **بعدها فقط** يُكشف المتوقّع والفرق (للمالك) → الوردية `CLOSED`. بلا عدّ → تبقى مفتوحة كاستثناء. ثم **سحب المبيعات** (المسؤول يستلم) وتُترك الفكّة لليوم الجاي. *(الي يعدّ غير الي يستلم قدر الإمكان.)*

### ٥.٩ إغلاق اليوم
كل الورديات مغلقة والكاش مسوّى → **إغلاق اليوم** → يُقفل تعديل عمليات اليوم إلا بصلاحية خاصة.

### ٥.١٠ الجرد
لكل مادة → النظام يُظهر المتوقّع → يُدخل المعدود → يُسجَّل **الفرق** كـ`COUNT/ADJUSTMENT` (لا يمسّ الحركات القديمة). عتبات مرنة: 🟢 0–3% · 🟡 3–5% · 🔴 فوق 5% (قابلة للتغيير).

### ٥.١١ إضافة مخزون / شراء
مادة → كمية + **تكلفة** (+ اسم مورد نصّي اختياري) → حركة `PURCHASE` `+` بتكلفتها (تحدّث المتوسط المرجّح). *(الفكّة/الكمية بالوحدة الأساس داخلياً: كيلو→g، لتر→ml.)*

### ٥.١٢ لوحة المالك
أول شاشة: **جملة واضحة** «اليوم تمام ✅» أو «انتبه ⚠️ عندك N أشياء» → تحتها **الشاذّ** (إلغاء/إرجاع/no‑sale/هدر عالٍ/فرق درج/فرق مخزون) → ثم أرقام اليوم (مبيعات · كاش/بطاقة · ربح) لمن يريد التفصيل. تبويبات: اليوم · المخزون · الاستثناءات · التقارير/الربح · الإعدادات.

## ٦) الأمان (٣ طبقات + مراقبة)
1. **فرق الكاش** (يمسك سرقة الدرج). 2. **فرق المخزون** (يمسك البيع غير المسجّل). 3. **سجل التدقيق/الموافقات** (يمسك الإلغاء/الإرجاع/الخصم). + **تنبيهات موبايل للحرِج فقط** (إلغاء بعد دفع · إرجاع · فرق درج/مخزون عالٍ · تعديل مخزون · مجاني كبير). البيع الطبيعي/الهدر الطبيعي **بلا إشعار**.
**فلسفة النظام:** يُثبت **وين راحت الفلوس والمواد** — لا يتّهم.

## ٧) الواجهة واللغة (قاعدة على كل الشاشات)
- عربي سهل قصير · أرقام إنجليزية · أزرار لمس كبيرة · خطوات قليلة · الخلفية تسوّي الحساب.
- **الباريستا يشوف:** الطلب الحالي · «طلباتي» (عدد وتفاصيل شفته، إعادة طباعة، بلا مبالغ) · حالة بسيطة للمخزون · أزرار (دفع/هدر/مشروب موظف/إغلاق وردية).
- **الباريستا لا يشوف:** مجموع المبيعات · المتوقّع بالدرج · الأرباح · التكاليف · التقارير · بيانات غيره.
- رسائل الخطأ بسيطة: «صار خلل بسيط، جرّب من جديد».
- ترجمة المصطلحات: فرق الدرج/راحت قهوة أكثر من اللازم/التكلفة/الربح/فكّة البداية/إلغاء/إرجاع/سجل العمليات — لا مصطلحات إنجليزية بالواجهة.
